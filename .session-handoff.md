**A0 root cause, in full** (worth not rediscovering): the forfeit charge is a
`navigator.sendBeacon` issued immediately before `router.push`. A **page-scoped**
`page.waitForRequest` does not reliably observe a beacon whose document is being torn down
by that navigation; the **context-scoped** `ctx.on("request")` counter always does. The
WAIT and the ASSERTION were watching different channels, so they could disagree — and when
they did, the harness called a working app broken. Trigger was `a97540d` (briefing beats
held to 5.2s), which updated `station_assert.mjs` but not this suite. Second defect, worse:
`const seen = waitForfeit(page)` was created before the click and awaited after, so any
throw in between left it dangling → unhandled rejection → node died → `set -e` aborted the
whole suite → **every later harness silently skipped**. Fixed by polling the counter the
assertion already uses. Mutation-verified: breaking `chargeForfeit` fails exactly scenarios
1/5/7; breaking the separate unmount beacon fails exactly hard-nav.

**A3 root cause**: `.aurora-page-enter:has(.aurora-admin)` is a COLUMN flex container, so
`.aurora-admin` is a cross-axis item — and its own `margin: 0 auto` (auto cross-axis
margins) **disables stretch**, leaving it fit-content at 385px in a 360px viewport;
`.aurora-main-scroll` (`overflow-x: hidden`) then clipped 25px. **`min-width: 0` does NOT
fix this** — measured, it stayed at exactly 385: a fit-content item is never being shrunk,
so there is no automatic minimum to relax. `width: 100%` + `box-sizing: border-box` is what
binds it.
