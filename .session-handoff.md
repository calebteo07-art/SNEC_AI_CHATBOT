## 9. GOTCHAS & CONSTRAINTS
- **Isolated ship (CRITICAL):** origin/main is force-pushed by concurrent sessions. Before push:
  `git -C <wt> fetch origin` then `git -C <wt> rev-list --left-right --count origin/main...HEAD`.
  If origin advanced, rebase HEAD onto new origin/main (`git -C <wt> rebase origin/main`), re-run
  typecheck+build+harness, THEN `git -C <wt> push origin HEAD:main`. Never force-push main.
  Push auto-deploys Render prod → must be green first.
- **`.claude/worktrees/eyecon` has a REAL node_modules** (did `npm ci` there — Turbopack in Next 16
  REJECTS a node_modules junction pointing outside the worktree, so the memory's junction recipe
  does NOT work for `next build`; a real install is required). Do NOT re-junction. If you later
  `ExitWorktree`/remove, a plain removal is fine (no junction to protect).
- **cwd drift breaks the bash_guard hook** (`.claude/hooks/bash_guard.py` runs via a relative path).
  NEVER use a bare `cd` in the Bash tool — it persists and the hook then fails with "can't open
  file …/bash_guard.py". Use subshells `( cd frontend && npm ... )` or `git -C <path>`, or reset
  via the PowerShell tool `Set-Location <worktree-root>`. Bash and PowerShell SHARE cwd.
- **:3000 is a concurrent session's dev/harness server — do not test against it. Use :3010.**
  `scripts/start-harness.sh` hardcodes :3000 and "reuses" a live server → would test the WRONG
  build. Serve manually on :3010 (recipe §8).
- **Git policy (user standing rule):** after a completed task, stage + commit + push directly to
  `main` (no feature branch, no asking) — but VERIFY GREEN first (pytest/typecheck/build/harness).
  Stage only this task's files (tree carries unrelated concurrent-session dirt).
- Don't create/overwrite workflow files without explicit permission. Live Gemini text/image calls
  cost real money — keep MOCK_MODE; don't fire without go-ahead (not needed for this task).

  gate doesn't bounce them). `aurora_assert.mjs` main context sets `reportCustomized=true`; the
